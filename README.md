# evenus.app

The website for **EvenUS** — an app for two people who live together that
measures how money, time and mental load are actually shared, and suggests one
thing to swap each week.

Static HTML, generated by one Node script. No framework, no dependencies, and
the only client-side JavaScript is `src/dc/site.js`.

```bash
node src/build.mjs      # -> dist/
npm run serve           # build, then serve dist/ on :8080
```

## How this is built

`handoff/` holds the design bundle: seven `.dc.html` page prototypes plus a
shared header and footer.

**Those files are the source of truth, and the build RENDERS them rather than
transcribing them.** The handoff asks for pixel-for-pixel, and the surest way to
hit that is to use the designer's own markup instead of a retyping of it —
retyping 46 KB of hand-tuned spacing is how a build ends up 90% faithful in a way
nobody can point at. To change the design, change the file in `handoff/`.

What is *not* carried over is the prototype runtime (`support.js`), which the
handoff explicitly excludes. Every interaction is reimplemented in
`src/dc/site.js` as plain DOM code:

| | |
|---|---|
| Fairness calculator | Six sliders; the handoff's formula unchanged |
| Accordions | Single-open, first open, `aria-expanded` / `aria-controls` |
| Blog filter | Six categories, `aria-pressed`, live count |
| Scroll reveal | IntersectionObserver, 4-second failsafe, respects reduced motion |

`src/dc/hooks.mjs` annotates the rendered markup for that runtime.
**Every anchor it uses is asserted, and that assertion earns its keep:**
`stroke-dashoffset="57"` matches twice in the page because a phone mockup draws
the same ring, and `>87<` matches four times. Hooks are therefore scoped to the
section they belong to. A calculator that silently stops updating because a
colour moved is invisible in a screenshot — this fails the build instead.

## Two things the handoff does not contain

1. **A blog post template.** The bundle designs the blog index and stops. The
   article page is composed in `src/build.mjs` from the system's own parts — the
   shared chrome, the legal pages' prose column, the index's category chip.
2. **Real content.** The index ships 32 placeholder posts. The site has 115
   recovered ones, so the design's own `<sc-for>` is driven with those.

   The 32 placeholders carry real slugs — every one matches a recovered post —
   so their categories, titles and excerpts are treated as authoritative. The
   other 83 get a category from `src/dc/blogdata.mjs`.

## Layout

```
handoff/               the design bundle. EDIT HERE.
  HANDOFF.md           the full brief: tokens, type, per-screen spec
src/
  build.mjs            the whole build
  dc/render.mjs        renders .dc.html to static HTML
  dc/hooks.mjs         annotates it for the runtime, with assertions
  dc/site.js           the interactions, as plain DOM code
  dc/blogdata.mjs      categories and read times
  site/wordpress.mjs   pulls prose out of the archived pages
  recovered/blog/      115 archived posts
dist/                  generated; not committed
```

## Before launch

Three placeholders remain and the build prints them on every run:
`[COMPANY NAME]`, `[COMPANY ADDRESS]`, `[JURISDICTION]`. They live in
`handoff/Privacy.dc.html`, `handoff/Terms.dc.html` and
`handoff/Disclaimer.dc.html`. **Both app stores gate submission on those pages.**

## Hosting

**Vercel** builds and deploys on push; `vercel.json` carries the build command
and output directory. Without it Vercel serves 404s for everything, because
`dist/` is gitignored and a zero-config deploy finds no `index.html`.

**GitHub Pages** also deploys on push, via `.github/workflows/deploy.yml`.

`BASE_PATH` is the difference. A GitHub *project* site is served from `/<repo>/`,
so every root-relative link 404s without it — breakage that appears only after
deploying. It is applied at the write boundary rather than where links are
authored, because links also arrive from the recovered posts' own
cross-references, which no template controls.

Vercel serves from the domain root and needs **no** `BASE_PATH`. Do not copy the
workflow's value into Vercel's environment variables; it would prefix every link
and break the site in the opposite direction.

⚠️ **`.app` is on the browser HSTS preload list.** Every `.app` domain must serve
valid HTTPS — browsers refuse plain HTTP outright, with no click-through.

## The WordPress import

The original site was WordPress with Elementor and was deleted at its host. The
domain survived; the files did not. The Internet Archive had crawled it, so the
writing survived even though the theme, the stylesheets and every image did not.

`src/site/wordpress.mjs` imports **only the prose**. It is an allow-list, not a
strip-list, and that distinction is the whole design: removing the tags you
happened to notice leaves the ones you did not, which is exactly how a WordPress
footprint survives a migration.

**The build asserts it.** If `wp-content`, `elementor`, `googletagmanager` or
nine others reach the output, the build fails rather than printing a warning
nobody reads. It also fails on any unrendered design directive, any leftover
prototype event handler, and any link to a `.dc.html` file that does not ship.

Images were never archived, so posts are text-only.
